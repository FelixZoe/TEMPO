# 序舱完整配置指南

本页说明安装完成后如何配置序舱。部署同步服务请先看[自托管部署](/DEPLOYMENT)；本页只讲客户端入口、字段含义、凭据位置和验证方法。

## 功能配置索引

| 要配置的能力 | 客户端入口 | 必填内容 | 验证方式 |
| --- | --- | --- | --- |
| 多端同步 | 设置 → 自托管同步 | HTTPS 根地址、64 位同步密钥、设备名称 | “验证、保存并立即同步” |
| AI 助手 | 设置 → AI 助手 | 服务类型；直连模式还需 API Key | “测试连接”后执行一次摘要 |
| 天气 | 设置 → 天气与每日一句 | 和风天气 API Host、Key、Location ID、城市名 | “测试天气连接” |
| 每日一句 | 设置 → 天气与每日一句 | 无 | 开启后轻点收集箱顶部卡片刷新 |
| RSS | RSS → 订阅管理 | Feed 地址、来源分组 | 下拉刷新并打开一篇文章 |
| 软件更新 | 设置 → 软件更新 | 无 | 检查最新版并跳转 Release |

序舱面向一个人使用。不同设备填写相同同步地址和密钥，设备名称应各不相同。

## 多端同步

### 1. 服务端准备

先确认公网健康检查正常：

```bash
curl -fsS https://你的域名/health
```

预期返回 `{"status":"ok"}`。服务器地址必须使用 HTTPS；客户端只允许本机调试地址使用 HTTP。

### 2. 客户端填写

在每台设备打开“设置 → 自托管同步”：

```text
服务器：https://你的域名
同步密钥：.env 中 SYNC_TOKEN 的完整 64 位值
设备名称：iPhone / Android / Mac / Windows-PC
实时同步：开启
```

- 地址只填根地址，不要追加 `/v1/sync`、`/health` 或结尾参数。
- 域名反向代理必须把 `/v1/` 和 `/health` 转发到同步容器。
- 保存按钮会先验证，再写入安全存储，随后立刻拉取远端数据。
- 重装后填写原来的地址和密钥即可恢复服务器上已有的数据；仅保存在本地且尚未上传的内容无法恢复。

### 3. 实时同步的正常表现

- 前台设备通过变更长轮询被立即唤醒。
- 任务、完成状态和番茄钟阶段先本地落盘，再上传。
- 网络恢复后会自动补传；五分钟完整同步只负责兜底。
- iOS 被系统完全挂起时不能维持普通网络连接，回到前台会立即追平。

## AI 助手

### 推荐：由自托管服务器代理

在服务器 `.env` 中填写：

```dotenv
AI_BASE_URL=https://api.openai.com/v1/chat/completions
AI_API_KEY=你的服务端密钥
AI_MODEL=gpt-5.6-terra
```

执行 `docker compose up -d` 重新创建容器。客户端选择“序舱自托管”，会复用同步地址和同步密钥，不需要在每台设备重复填写模型密钥。

### 客户端直连

Apple 客户端支持 OpenAI、DeepSeek 和 OpenAI 兼容服务；Android / Windows 提供自托管、OpenAI 与 DeepSeek 预设。

| 服务 | 默认接口 | 默认模型 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1/chat/completions` | `gpt-5.6-terra` |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-flash` |
| 自定义兼容服务 | 填完整 Chat Completions 地址 | 使用服务商给出的模型 ID |

切换服务时会带入预设值；已经保存的自定义模型不会被应用升级强制覆盖。直连 API Key 只写入系统安全存储，不参与多端同步。

摘要提示词留空时使用应用内置提示词；只有需要固定语气或格式时才填写自定义提示词。配置完成后先测试连接，再用一篇 RSS 文章测试“摘要”和“翻译覆盖”。

## 天气与每日一句

天气使用自己的和风天气开发凭据；每日一句由 Hitokoto 获取，不需要密钥。两项内容显示在收集箱顶部，轻点卡片可以刷新。

### 和风天气字段

1. 在和风天气控制台创建项目与凭据。
2. 复制该项目分配的专属 API Host，例如 `abc123.re.qweatherapi.com`，不要填写 `https://` 和路径。
3. 填写 API Key。
4. 填写 Location ID，例如北京 `101010100`。
5. 城市名称只用于界面展示，应与 Location ID 对应。
6. 点击“测试天气连接”，成功后再保存。

天气 Key 保存在系统安全存储；Host、Location ID 和显示名称属于设备偏好。离线时应用继续显示最近一次成功缓存。

## RSS、翻译与 AI 动作

- 在“RSS → 订阅管理”添加标准 RSS / Atom 地址并设置来源分组。
- 阅读页优先提取正文；原站正文不完整时会使用网页阅读视图补全。
- 翻译使用当前 AI 配置并覆盖阅读正文，不另开一个重复页面。
- 摘要、自动标签、转任务等动作共用当前 AI 配置。
- OPML 用于批量导入或导出订阅；它不包含 AI Key 和同步密钥。

若订阅刷新失败，先在浏览器直接打开 Feed 地址，确认返回 XML 而不是登录页、Cloudflare 验证页或 HTML 首页。

## 模块与导航

iOS 一级底栏始终显示收集箱、今天、番茄钟、RSS 与设置五个独立入口，不使用“更多”聚合页面。可在“设置 → 导航顺序”中拖动排序。AI 不占一级导航，它作为任务与 RSS 场景中的动作出现。

导航顺序属于设备偏好，不同步到其他平台；各端保留自己的原生交互，但共用任务、专注与 RSS 数据语义。

## 更新与覆盖安装

- “设置 → 软件更新”读取 GitHub 最新 Release。
- iOS 点击更新会打开最新 IPA 下载地址；能否覆盖安装取决于新旧包名、签名证书和描述文件是否一致。
- Android 使用稳定签名时可覆盖安装，并可使用 Release 中的增量补丁；签名不同必须先卸载。
- Windows 安装包支持同路径覆盖安装；便携版应先退出托盘进程再替换目录。
- macOS 未签名构建首次打开可能需要在系统隐私与安全中确认。

## 凭据与同步范围

| 数据 | 存放位置 | 是否同步 |
| --- | --- | --- |
| 任务、完成状态、番茄钟、RSS 状态 | 本地数据文件 + 可选同步服务 | 是 |
| 同步密钥 | 系统安全存储 | 否 |
| AI 直连 API Key | 系统安全存储 | 否 |
| 天气 API Key | 系统安全存储 | 否 |
| 导航顺序 | 设备偏好 | 否 |

## 快速排障

| 现象 | 首先检查 |
| --- | --- |
| 测试连接失败 | 地址是否为 HTTPS 根地址；`/health` 是否为 200；密钥是否完整 |
| 保存后没有旧数据 | 是否连接了原来的域名和密钥；远端 `store.json` 是否存在 |
| 设备间有明显延迟 | 代理是否缓存 `/v1/changes`；读取超时是否大于 25 秒 |
| AI 显示未配置 | 自托管容器是否有 `AI_API_KEY`；直连模式是否已保存 Key |
| 天气不显示 | 专属 Host 是否只填域名；Key 和 Location ID 是否属于同一项目 |
| 覆盖安装失败 | Bundle ID / 包名和签名身份是否与旧版一致 |

服务端命令、反向代理、备份和容器日志见[自托管部署](/DEPLOYMENT#排障)。
